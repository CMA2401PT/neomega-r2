# neomega-r2：统一的格子射线渲染

R2 研究用同一条射线管线绘制完整方块和复杂方块。射线先穿过空间格子，再对格内对象求交：完整立方体直接确定命中面，栏杆、花、火等模型只检查本格内预生成的表面。两者共用由近到远的命中顺序与透明合成，不再由两个场景绘制器交换深度和加载覆盖范围。

目标是让渲染和加载规则统一，并在实际场景中保持可用性能，不要求每个场景都胜过传统网格。当前是独立的静态场景研究原型，尚未接入真实存档流式加载、方块实体和动态对象。

## 数据怎样流动

模型只在生成资源时解析一次。每个方块状态得到一个共享模型编号，完整立方体引用六面贴图描述，复杂模型引用三角面列表。重复三角面在全局只保存一次。

越界模型在生成时按整数格边界裁切。裁切交点同步插值 UV，并把每个片段平移到目标格的局部坐标；只分割原来的表面，不给切口添加封口。这样既保留形状和纹理，也避免射线回查邻居。

加载时按方块状态填入模型编号，再按照已经算好的偏移把裁片编号放入目标格子。一个格子可以同时拥有本格模型和若干外来裁片，保存的都是索引。加载阶段不解析模型、不裁切、不剔面，也不合并网格；将来接存档仍需要解码方块数据和转换状态。

```text
生成资源：方块模型 → 按格预裁切 → 共享表面、贴图与片段编号
加载场景：方块状态 → 查表 → 将编号放进对应格子
绘制画面：射线进格子 → 快速面求交或格内模型求交 → 采样并合成
```

空间层次合并空气和相同的完整立方体，帮助射线跳过大块空域或均匀介质。复杂模型和含裁片的格子保留逐格求交，不能把一整片栏杆误当作实心立方体。

透明贴图分两种处理：Cutout 像素未通过阈值时继续找后面的命中；Blend 表面按命中距离合成。玻璃、水仍采用同组介质的边界规则，内部接缝不贡献颜色，颜色不会随穿过厚度持续加深。水暂时仍是完整高度的立方体。

## 代码与资源边界

`catalog.go` 定义共享模型表，`scene.go` 只用编号构造实验场景与分发裁片。`cmd/r2` 提供数据和页面。`web/ray.frag` 包含空间遍历、两种求交和统一合成；`web/main.js` 负责 WebGL 资源、相机与计时。页面没有场景顶点缓冲，唯一的屏幕三角形用于发射射线。

需要更新模型资源时才使用 `cmd/build-models`。它读取 `sourceassets` 中的固定输入，输出 `assets` 中的状态表、模型表、三角面索引和表面数据。`internal/sourcegeometry` 是为读取输入快照复制的格式解码器，仅由这个生成命令使用。

输入资源与解码器来自 viewer-core `8afee71`，包括 Java 26.3 的静态模型、原始图集，以及已经验证的完整方块材质与独立 mip。代码和资源均已复制，本模块不导入 `neomega-viewer-core` 或 `neomega-viewer`。生成命令使用工作区的 `neomega-blocks` 状态目录；运行服务不依赖模型解析器。许可证保留在 [LICENSE](LICENSE) 与 [资源说明](sourceassets/THIRD_PARTY_NOTICES.txt)。

运行 `go generate ./neomega-r2` 得到的资源统计：

| 内容 | 数量 |
|---|---:|
| 快速立方体状态 | 2768 |
| 通用静态模型状态 | 19562 |
| 共享模型及裁片 | 16753 |
| 需要跨格裁切的模型 | 843 |
| 去重后三角面 | 134382 |
| 模型对三角面的索引 | 459930 |
| 单个裁片最多三角面 | 120 |

另有 47 个状态在源静态表中没有可用表面，名单保存在 `assets/catalog.json`。这里包括没有连接且没有柱子的墙等空模型状态，不能把这个数字当成完整游戏内容的缺失清单。原型只验证已选用的静态输入，不代表方块实体的 NBT 内容和动画已经支持。

## 运行与检查

从工作区根目录启动，默认端口为 2413：

```sh
go run ./neomega-r2/cmd/r2
```

浏览器打开 <http://127.0.0.1:2413>。可以切换综合场景、密集栏杆、花朵、立方体、跨格裁片以及两种厚度的玻璃。拖动旋转视角，WASD 平移，Q/E 升降。热图中的红色表示遍历步数，绿色表示模型三角面测试数。

修改着色器或页面时，可直接读取网页目录，避免每次重新编译内嵌资源：

```sh
go run ./neomega-r2/cmd/r2 -web ./neomega-r2/web
```

修改资源生成器后重新生成，再检查模块边界与构建：

```sh
go generate ./neomega-r2
./check.sh neomega-r2
node neomega-r2/experiment/check.cjs
```

浏览器检查默认连接 2413。可以通过 `R2_URL` 更改地址，通过 `PLAYWRIGHT_MODULE` 和 `CHROME` 指定本机 Playwright 与 Chrome。Go 检查验证裁切的面积、UV、格内边界和片段组合；浏览器检查验证实际 GPU 画面、透明厚度与层次遍历一致性。实测条件、结果和后续需要验证的范围见 [实验记录](experiment/README.md)。

## 后续验证边界

接入真实存档时，需要验证裁片随来源方块跨区域发布和撤销，避免加载边界漏掉裁片。动态模型、方块实体文字和动画需要可更新的描述或实例数据，不能仅凭一个静态方块状态包办。

通用模型目前使用首帧原图采样，尚未给复杂表面的缩小过滤和动画建立完整方案。完整立方体沿用独立 mip 和方向过滤。稠密 Cutout 场景会让射线穿过多个模型，通用表面测试仍可能成为瓶颈；如果有必要，可以在预生成的复杂模型内增加小型加速结构，而不用引回另一条场景绘制管线。

这个结构采用格子加速局部求交的基本思路，相关背景可参见 [PBRT 的 Uniform Grid 说明](https://pbrt.org/chapters/pbrt-2ed-chap4.pdf)。R2 的具体实现和性能判断以本地实验为准。
