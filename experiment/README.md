# 固定版本的真实存档、采样与特殊对象验证

本报告及以下命令对应提交 `4a37e99`，复现时应在该提交的独立检出目录运行。它记录固定窗口研究版，不描述当前核心与应用的接口。当前流式应用的命令和结果见 [应用验收](../../apps/neomega-viewer-r2/experiment/README.md)。

这里用固定输入检验统一射线渲染的画质和成本。真实存档测试使用“新天堂”，比较旧版纯色 brickmap 和 R2；独立特殊场景检查活动部件、私有贴图、透明孔洞和遮挡。性能以实际画布像素和每帧 GPU 时间为准，不把浏览器 60 Hz 的回调上限当成最大吞吐量。

## 存档范围与相机

测试设备为 Apple M4，浏览器为桌面 Chrome，后端为 ANGLE Metal。测试运行于 headless Chrome，像素比为 1，关闭 MSAA，FOV 为 65°。这些结果只代表这台设备，不代表 Windows 显卡或远程桌面的呈现帧率。

存档路径为 `/Users/dai/Downloads/新天堂`。窗口是 12×12 个 128 方块区域，即 **1536×1536×512**，Y 为 -64..447。原 viewer 也把高度范围 -64..319 补齐到 512 格。R2 近景水平范围为半径 8 区块的圆，上下各 9 个 section；其他位置使用简化体素外观。所有区域加载完成后才开始测量。

| 视点 | 相机坐标 | 朝向目标 | 非空近景 section | 非空远景 section |
|---|---|---|---:|---:|
| 高空全景 | 1280,271,1280 | 1120,185,1080 | 4 | 64392 |
| 林冠近景 | 1280,78,1280 | 1210,70,1200 | 1086 | 63310 |

高空视点几乎没有近景复杂模型，所以不能只用它判断近景成本。页面提供这三个测试视点的跳转菜单。R2 的窗口目前按加载时的观察中心固定，连续移动的测试没有包含跨窗口流式重建。

## 与旧版纯色 brickmap 对照

旧服务使用 viewer `2bec12b5885fdc320d2f39da70331d897165a88d` 的现有编译版，`go version -m` 确认提交和干净构建状态；设置 `NEOMEGA_BRICKMAP_TEXTURES=0`。绘制代码从对应 core `fcdaeae` 原样提取，测试页面只负责上传窗口、设定相机和计时。

旧版对照整窗使用简化体素，没有近景精细网格，也没有小地图。R2 在同一覆盖范围内保留半径 8 的复杂静态模型和完整方块贴图。因此这张表比较的是旧版纯 brickmap 的成本与 R2 完整静态路径的成本，不是旧应用整页性能对照。两边均关闭雾效，使用同一透视相机。

执行 `node neomega-r2/experiment/compare.cjs`，每档取得至少 120 个 GPU 查询结果，舍弃前 40 个。每帧读回一个像素，等待 GPU 完成，另外记录包含提交与等待的时间；读回发生在 GPU 查询结束后。这样避免仅凭 CPU 已排队的帧数推断 GPU 吞吐量。原始结果见 [comparison.json](results/world/comparison.json)。

| 分辨率 | 视点 | 旧版 GPU 中位数 | R2 GPU 中位数 | R2 相对吞吐量 |
|---|---|---:|---:|---:|
| 1920×1080 | 高空全景 | 12.22 ms | 15.01 ms | 81% |
| 1920×1080 | 林冠近景 | 12.01 ms | 12.10 ms | 99% |
| 1920×1080 | 建筑近景 | 13.60 ms | 13.93 ms | 98% |
| 2560×1440 | 高空全景 | 16.64 ms | 23.78 ms | 70% |
| 2560×1440 | 林冠近景 | 16.01 ms | 20.62 ms | 78% |
| 2560×1440 | 建筑近景 | 16.11 ms | 23.52 ms | 68% |

相对吞吐量按“旧版耗时 / R2 耗时”计算。720p、1080p、1440p 三档共九组结果为 68%～99%，满足“至少保留旧版一半吞吐量”的实验标准。设备调频和浏览器调度会影响绝对数值；这不是硬件峰值性能排名。

## 60 帧与多采样的代价

执行 `node neomega-r2/experiment/quality.cjs`，使用相同高空和建筑视点。每档至少取得 100 个 GPU 查询，舍弃前 30 个，并用单像素读回交叉检查完成时间。结果见 [quality.json](results/world/quality.json)。

| 实际像素 | 每像素射线 | 高空 GPU 中位数 / P95 | 建筑 GPU 中位数 / P95 |
|---|---:|---:|---:|
| 1600×900 | 1 | 11.86 / 14.69 ms | 11.34 / 14.38 ms |
| 1920×1080 | 1 | 14.84 / 16.10 ms | 13.90 / 15.02 ms |
| 2560×1440 | 1 | 23.68 / 24.63 ms | 23.49 / 24.32 ms |
| 1920×1080 | 2 | 28.54 / 31.24 ms | 27.56 / 30.79 ms |
| 1920×1080 | 4 | 55.29 / 64.76 ms | 55.11 / 63.82 ms |
| 1280×720 | 2 | 15.15 / 16.87 ms | 14.14 / 16.99 ms |
| 960×540 | 2 | 11.13 / 14.64 ms | 12.43 / 13.51 ms |
| 800×450 | 4 | 14.42 / 18.30 ms | 13.03 / 15.84 ms |
| 640×360 | 4 | 12.23 / 15.25 ms | 11.51 / 15.37 ms |

在已测档位中，**原生 1080p、单射线可以维持约 60 帧，900p 留有更多余量；1440p 超过帧预算**。1080p 高空视点包含提交和等待的 P95 为 16.5 ms，余量有限。两条射线的 720p 略超 P95 预算；四条射线即使 800×450 也并不稳妥。多采样主要改善几何边缘，没有实现时间累积、重投影或降分辨率重建。

同尺寸原图可直接比较：[旧版纯色](results/world/baseline-1080p.png)、[R2 单射线](results/world/native-1080p.png)、[R2 四射线](results/world/four-rays-1080p.png)、[高空全景](results/world/aerial-1080p.png)。图片均为 1920×1080，未缩放后再保存。

同一脚本还在建筑视点以 1080p 单射线进行 10 秒小幅移动。最后 240 个样本的 GPU 中位数为 14.37 ms、P95 为 16.01 ms；浏览器回调间隔中位数为 16.7 ms、P95 为 16.8 ms，原始值见 [motion.json](results/world/motion.json)。回调间隔不是屏幕呈现时间保证。

## 加载成本怎样解释

`comparison.json` 同时记录每个窗口的加载数据。传输约 82～83 MiB，包含近远景共享的压缩调色板索引；近景不是另一份完整区块下载。Go 读取与传输的墙钟时间约 1.3～1.4 秒，后台线程准备约 1.8～2.0 秒，GPU 上传调用约 30～40 ms，整个窗口约 3.2～3.4 秒。上传调用时间不等于等待 GPU 完成时间。

`serverMS` 是四个并行请求通道累计的服务端工作时间，不能直接当作用户等待时间。实验没有清空操作系统文件缓存，也没有模拟远程网络。窗口一次准备完成后发布，没有验证首屏渐进加载。Go 的未知状态计数为 0，但这不表示方块实体、含水附加层和所有动画均已支持。

## 特殊场景与正确性

`special.cjs` 使用 1920×1080 固定相机和固定动画时间，比较开启与关闭空间层次的画面，确认活动部件不会被粗层跳过；再改变时间检查书页实际运动。单像素探针分别检查旗面的透明孔、实色部分和石英遮挡。旗面使用合成测试图，不是完整旗帜 NBT 处理器。

测试中改变动画时间后有 6830 个像素变化；透明孔和石英遮挡的探针与移除特殊对象后的像素完全相同，实色旗面则确实改变像素。结果见 [special.json](results/world/special.json) 和 [特殊场景原图](results/world/special.png)。该相机下还存在 1 个静态方块边界像素的遍历舍入差异，关闭全部活动对象后仍存在；测试单独识别它，并要求活动对象不引入额外差异。这个静态边界精度问题尚未消除。

静态场景原有的玻璃厚度、跨格片段和逐格遍历对照由 `check.cjs` 继续验证，[当前回归结果](results/world/static-regression.json) 中五个场景的最大通道差均为 0，玻璃厚度检查通过。早期小场景的固定输入和结果见 [静态实验](static.md)。这些测试没有证明连续世界更新时的候选登记和撤销，也没有覆盖任意变形模型。

## 复现

启动 R2：

```sh
go run ./neomega-r2/cmd/r2 -listen 127.0.0.1:2413 \
  -web ./neomega-r2/web -world '/Users/dai/Downloads/新天堂'
```

准备对应旧版 viewer 二进制，然后单独启动对照页。脚本从本地 core 的 Git 历史提取着色器和砖池，使用固定版本 esbuild 打包；旧服务监听 2423，对照页监听 2424：

```sh
node neomega-r2/experiment/serve-baseline.mjs \
  /tmp/brickmap-mip-baseline '/Users/dai/Downloads/新天堂' fcdaeae
```

逐一执行，避免多个基准同时争用 GPU：

```sh
node neomega-r2/experiment/compare.cjs
node neomega-r2/experiment/quality.cjs
node neomega-r2/experiment/special.cjs
node neomega-r2/experiment/check.cjs
./check.sh neomega-r2
```

默认输出在 `/tmp/r2-compare`、`/tmp/r2-quality`、`/tmp/r2-special-check` 和 `/tmp/r2-check`。工具路径通过 `PLAYWRIGHT_MODULE`、`CHROME` 指定；特殊场景与画质测试可通过 `R2_URL` 指定 R2 服务。`world.cjs` 提供不强制读回的分辨率扫描，适合观察回调与排队行为；直接判断相对吞吐量使用 `compare.cjs` 的同步结果。
